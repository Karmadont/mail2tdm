# mail2tdm на Python — установка и запуск

Программа читает письма из Outlook и отправляет их в канал TDM через
официальный Bot API.

**Docker не нужен.** Он нужен был только разработчику для проверок на Mac.
На рабочем компьютере требуется лишь Python и два файла программы.

## Что нужно на рабочем компьютере

| Что | Зачем | Нужны ли права администратора |
|---|---|---|
| Python 3.8 или новее | Запускать программу | Нет, если уже установлен |
| Файлы `mail2tdm.py` и `tdm_client.py` | Сама программа | Нет |
| Файл `config.ini` | Токен и настройки | Нет |
| Надстройка `pywin32` | Чтение Outlook (только для шагов 5–6) | Нет |

Проверить, что Python есть — открой «Командную строку» (Пуск → набери `cmd`) и введи:

```
python --version
```

Если ответит номер версии — всё в порядке.

## Шаг 1. Положить файлы

Создай на рабочем компьютере папку, например `C:\mail2tdm`, и положи туда:

- `mail2tdm.py`
- `tdm_client.py`
- `config.example.ini`

Копируй файлы целиком (флешка, сетевая папка, вложение), не пересоздавай
их через Блокнот.

## Шаг 2. Самопроверка — до всякой настройки

В «Командной строке»:

```
cd C:\mail2tdm
python mail2tdm.py --selftest
```

Токен, интернет и Outlook для этого **не нужны**. Программа сама поднимает
внутри себя поддельный сервер и проверяет всю цепочку: отправку русского
текста, загрузку файла, реакцию на неверный токен.

Должно закончиться словами **«ВСЁ ИСПРАВНО»**. Если нет — пришли весь вывод.

## Шаг 3. Заполнить настройки

Скопируй `config.example.ini` в `config.ini` и заполни:

- `BaseUrl` — адрес сервера Bot API;
- `Token` — токен от бота Bot Creator (**никому не пересылать**);
- `WorkspaceId` и `GroupId` — открой **веб-версию TDM**, зайди в нужный канал,
  оба числа будут в адресной строке браузера.

`TestMode=1` пока не трогай — это защита от случайной рассылки.

## Шаг 4. Проверить связь с TDM

```
python mail2tdm.py --check
```

Программа спросит у сервера, принимает ли он токен, и покажет каналы,
в которых состоит бот. **Ничего никуда не отправляется.**

Если пишет, что сервер не ответил — скорее всего, к серверу TDM есть доступ
только из рабочей сети. Тогда этот шаг делается именно на рабочем компьютере.

## Шаг 5. Подключить чтение Outlook

```
pip install --user pywin32
```

Права администратора не нужны. Затем открой Outlook (программа работает
с уже открытым профилем — пароли ей не нужны) и запусти:

```
python mail2tdm.py --once
```

При `TestMode=1` программа **ничего не отправит**, а запишет в журнал,
что *было бы* отправлено. Посмотри журнал `mail2tdm.log` — убедись, что
письма читаются и текст выглядит правильно.

## Шаг 6. Включить боевой режим

Когда журнал устраивает:

1. В `config.ini` поставь `TestMode=0`.
2. Отправь одно тестовое сообщение:

```
python mail2tdm.py --test-message
```

3. Проверь, что оно появилось в канале TDM.
4. Запусти постоянную работу:

```
python mail2tdm.py --watch
```

Программа будет проверять почту раз в минуту. Останавливается по Ctrl+C.

## Вложения

По умолчанию `SendAttachments=0` — программа только пишет в сообщении названия
приложенных файлов. Это безопасный старт.

Когда убедишься, что всё работает, можно поставить `SendAttachments=1` —
тогда файлы будут загружаться в хранилище TDM и отправляться в канал.

## Если что-то пошло не так

Пришли разработчику файл журнала `mail2tdm.log`.

**В журнале нет токена** — программа специально его не записывает.
Но перед отправкой всё равно пробегись глазами: там будут темы писем
и адреса отправителей.

## Чего делать нельзя

- **Не присылать токен в переписке** — ни разработчику, никому. Он даёт право
  писать в канал от имени бота.
- **Не класть `config.ini` и журналы в репозиторий** — он публичный.
  Это уже запрещено в `.gitignore`.

## Ограничения сервера

- не более 60 запросов в минуту (программа сама выдерживает паузу);
- бот пишет только в те каналы, куда его добавили.
