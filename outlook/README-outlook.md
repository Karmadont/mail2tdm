# Макрос Outlook: пересылка задач в TDM

Это «скелет» — рабочая основа. Заработает, когда техподдержка TDM выдаст доступ
и бот **Bot Creator** выдаст токен.

## Что здесь лежит

| Файл | Что это |
|---|---|
| `Mail2TDM.bas` | Основной код: отбирает письма, оформляет текст, отправляет в TDM |
| `ThisOutlookSession.vba.txt` | «Сторож»: замечает новые письма и передаёт их в основной код |
| `config.example.ini` | Образец файла настроек (без токена) |

## Порядок действий

### Шаг 1. Получить доступ (без этого дальше нельзя)

1. Написать с корпоративной почты на `tdm-helpdesk@mos.ru` — запросить доступ к боту **Bot Creator**.
2. Через Bot Creator создать бота, командой `/token` получить токен доступа.
3. **Добавить бота в тот канал**, куда должны попадать задачи.

### Шаг 2. Создать файл настроек

1. Нажать **Win+R**, вставить `%APPDATA%`, нажать Enter.
2. Создать папку `mail2tdm`.
3. Положить в неё файл `config.ini` по образцу `config.example.ini` и заполнить.

Как узнать `WorkspaceId` и `GroupId`: открыть **веб-версию TDM** в браузере,
зайти в нужный канал — оба числа будут прямо в адресной строке.

### Шаг 3. Проверить связь ДО настройки Outlook

Запустить проверялку `tools/tdm-check.ps1` (см. соседнюю папку `tools`).
Она скажет, принимает ли сервер токен, и покажет ID групп, где состоит бот.

### Шаг 4. Установить макрос

1. В Outlook нажать **Alt+F11**.
2. `Insert -> Module`, переименовать модуль в `Mail2TDM`.
3. **Скопировать текст** `Mail2TDM.bas` и **вставить** в модуль.
4. Открыть слева `ThisOutlookSession`, **скопировать и вставить** туда текст из
   `ThisOutlookSession.vba.txt`.
5. Перезапустить Outlook.

> **Важно:** именно копировать-вставить, а **не** импортировать файлы.
> При импорте могут испортиться русские буквы (мы уже наступали на эти грабли).

## Безопасность: начинать только с тестового режима

В настройках по умолчанию стоит `TestMode=1`. В этом режиме **ничего не
отправляется** — программа только записывает в журнал, что *было бы* отправлено.

Журнал: `%APPDATA%\mail2tdm\mail2tdm.log`

Сначала убедиться по журналу, что:
- нужные письма попадают в обработку, а лишние — отсеиваются;
- текст задачи оформлен так, как надо.

И только потом поставить `TestMode=0`.

## Что НЕЛЬЗЯ класть в этот репозиторий

Репозиторий публичный. Сюда **не должны** попадать:

- настоящий `config.ini` (в нём токен);
- журнал `mail2tdm.log`;
- PDF с документацией TDM;
- письма (`.msg`, `.eml`, `.pst`).

Всё это уже перечислено в `.gitignore`.

## Ограничения сервера

- не более **60 запросов в минуту** и 3000 в час на одного бота;
- бот не может создавать группы и каналы — только писать в те, куда его добавили.

## Чего пока нет (доделаем после проверки на живом боте)

- Тонкая настройка внешнего вида сообщения под ваши реальные письма
  (сейчас в `BuildMessage` простой шаблон: тема, отправитель, дата, текст).
- Пересылка вложений (в Bot API это отдельный метод `sendFile`).
- Защита от повторной отправки одного и того же письма.
